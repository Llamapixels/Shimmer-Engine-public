1. Project

Working name: Advance Studio

Goal: Build a GB Studio-like game creation environment for the Game Boy Advance.

The eventual workflow should look like:

                ADVANCE STUDIO
                     │
          ┌──────────┴──────────┐
          │                     │
       PC Editor            Project Data
          │                     │
          └──────────┬──────────┘
                     ↓
                 Compiler
                     ↓
                 GBA ROM
                     ↓
              ┌──────┴──────┐
              ↓             ↓
             mGBA        Real GBA

The goal is not simply to make a GBA game. The goal is to create a reusable engine/runtime plus a PC editor that can generate complete .gba games.

Operating system

Development environment

Important preference:

Current Windows project location:

C:\Users\User\Desktop\gba studio

WSL sees it as:

/mnt/c/Users/User/Desktop/gba studio

Because the directory contains a space, the devkitPro recursive Makefile had path problems.

A WSL bind mount was created:

which points to:

/mnt/c/Users/User/Desktop/gba studio

This allows the build system to see a space-free path while the actual files remain on Windows.

8. First Build Problem

The official devkitPro Makefile uses a recursive build:

$(BUILD):
	@[ -d $@ ] || mkdir -p $@
	@$(MAKE) --no-print-directory -C $(BUILD) -f $(CURDIR)/Makefile

Because the project is inside:

/mnt/c/Users/User/Desktop/gba studio/

the space caused the recursive make invocation to interpret:

gba studio

as separate arguments.

This caused errors such as:

make[1]: /mnt/c/Users/User/Desktop/gba: No such file or directory

A symlink was attempted:

ln -s "/mnt/c/Users/User/Desktop/gba studio" ~/gba_studio

but this didn't solve the problem because Make ultimately resolved the underlying Windows path.

A WSL bind mount was then created:

mkdir -p ~/advance-build

sudo mount --bind \
"/mnt/c/Users/User/Desktop/gba studio" \
~/advance-build

Now the project can be accessed through:

~/advance-build

without a space in the path.

10. First Test Program

The initial test program was a direct Mode 3 framebuffer test.

Core code:

#include <gba.h>

int main(void)
{
    irqInit();
    irqEnable(IRQ_VBLANK);

    SetMode(MODE_3 | BG2_ON);

    volatile unsigned short *videoBuffer =
        (volatile unsigned short *)0x06000000;

    for (int y = 0; y < 160; y++)
    {
        for (int x = 0; x < 240; x++)
        {
            videoBuffer[y * 240 + x] =
                RGB5(8, 16, 24);
        }
    }

    while (1)
    {
        VBlankIntrWait();
    }

    return 0;
}

mGBA displayed the resulting blue screen.

11. Why Mode 3 Was Only a Test

We do not want to build Advance Studio around framebuffer rendering.

The GBA has dedicated graphics hardware that should be used.

The actual engine should primarily use:

Backgrounds
Tilemaps
Tiles
Palettes
Scrolling
Sprites
OBJ hardware
OAM
Sprite tiles
Sprite palettes
Animation
GBA hardware
VRAM
OAM
Palette RAM
DMA
VBlank

Affine backgrounds

This will make the resulting games actually behave like proper GBA software.
